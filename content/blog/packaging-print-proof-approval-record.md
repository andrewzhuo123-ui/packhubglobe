# How do I document packaging print proof approval?

I can review every panel carefully and still send an ambiguous approval. The printer needs to know which file can run and which comments remain open.

**I document packaging print proof approval with one revision record, numbered corrections, named reviewers and a release instruction tied to the exact file. I close each correction against the returned proof and treat any later artwork change as a new approval decision.**

My review record starts when the supplier sends the first PDF. I keep the technical checklist beside it and use the record to move decisions from one revision to the next.

## What do I identify before anyone marks the proof?

A comment on the correct panel can become the wrong instruction if two PDFs share a name. I set the baseline before I ask for review.

**I record the job number, SKU, dieline revision, proof revision, receipt date and exact filename. I keep the supplied PDF in a shared review location and distinguish it from reference artwork and marked copies.**

### I make the incoming proof identifiable

I start with the supplier's file and keep an unchanged copy. In a sample job called BX-42, the incoming proof might be BX-42-proof-R02.pdf, for a carton on dieline D05. I enter both versions because artwork can change without a change to the structure, and a new structure can make otherwise correct artwork unusable. I ask the supplier to name the drawing or dieline if the email only says that the proof is new. I leave the review open until I can tie it to a specific file.

### I assign the review before collecting edits

I put the PDF and a separate annotated copy beside the record. I ask the artwork owner to check the layout and brand elements, the product owner to check copy and SKU identity, and the production contact to confirm output details. A small team can assign several roles to one person. The record still names the person who owns each decision. I link the [dieline preparation guide](/guides/prepare-packaging-dielines/) for the information that should have reached the artwork owner before the proof was issued.

I also list what the file is meant to prove. A flat PDF may show the layout, copy and position of a code. If I need evidence about how a fold looks after assembly or how a finish reads under light, I assign that evidence separately. That distinction keeps someone from closing the physical approval just because the PDF review is complete.

## How do I turn markup into corrections a supplier can follow?

Several reviewers can circle the same area and request incompatible fixes. I collect their comments in one list before returning the marked file.

**I give each correction an ID, location, current condition, requested result and close criterion. I resolve conflicting requests internally and send one list alongside the marked copy.**

### I write observable requests

A comment like “move this up” depends on which viewer opens the file and how they interpret the panel orientation. I identify the panel by its name and use the approved drawing as the reference. For example, P03 could read: “Rear panel, lower block. Replace the two-line care statement with the text in the approved copy sheet, row 12. Keep the clear area around the barcode as specified by the retailer.” The requested result describes what I will check when the proof comes back. I avoid inserting a made-up spacing value where the drawing or scan specification should govern.

| ID | Location | Requested result | Close evidence |
| --- | --- | --- | --- |
| P01 | Front panel | Replace illustration with file ART-04 | Returned PDF shows the approved illustration |
| P02 | Side panel | Correct variant name against SKU list | Exact spelling matches that SKU |
| P03 | Rear panel | Replace care text and retain code clear area | Revised panel and code position reviewed |

### I distinguish decisions from questions

I reserve a status for questions that need an answer before I can write a correction. If a spot plate appears on the wrong panel, I ask whether the supplier sees the same plate in their production file. I can inspect separations and simulate overprinting in Adobe Acrobat Pro when the PDF supports that review.[^1] I ask the printer to confirm settings on their side. My [print proof checklist](/guides/packaging-print-proof/) supplies the checks, and the numbered list records the actions that came out of them. I tell the supplier which comments block release so a courtesy reply cannot be mistaken for resolution.

## How do I check the returned revision?

A revised PDF can correct the highlighted problem and introduce a change elsewhere. I compare the new file with the prior revision before closing comments.

**I match each correction to evidence in the returned revision, inspect nearby panels and ask about unexplained changes. I record who checked each item and leave any unresolved item open.**

### I check both the requested result and its neighbours

I enter the supplier's new filename and receipt date, then compare the two revisions panel by panel. When I requested a longer ingredient or care line, I check whether the new line pushed against a seam or moved the code. When a new logo replaced a previous version, I look for a duplicate on an alternate panel. For text changes I compare exact copy. For layout changes I check the result against the drawing and visual context. I leave a brief note for every closed item, such as “P02 closed against R03, side panel, variant name matches SKU register row 7.”

### I ask for the right evidence at the right stage

If the proof contains a retail barcode, I check whether it carries the intended data and whether the placement remains compatible with the package. A phone scan can be a quick check of data or a link. When the channel requires verification of printed symbol quality, I ask for the appropriate verifier report on the relevant printed sample. GS1 describes how printed barcodes can be measured with a compliant verifier.[^2] I record the device or report used and the revision that was tested.

If the barcode sits on a label, I also confirm the supplied format against the [label roll direction guide](/guides/label-roll-direction/). A readable digital layout will not tell me whether the labels feed into the applicator in the intended orientation. I close the print correction against the PDF and leave the applicable roll or printed-sample check with its own owner.

## What do I put in a production release instruction?

A thread full of resolved comments can still leave a supplier guessing whether production may start. I send a separate instruction when the required decisions are complete.

**I state the job, exact approved proof file, approved scope and remaining gates. I send the release to the supplier, retain their acknowledgment and reopen review if they substitute a file or change the artwork.**

### I keep the release specific enough to hand over

An example message reads: “Job BX-42. Artwork approved for SKU BX-42-BL using BX-42-proof-R03.pdf on dieline D05. Proceed with the printed sample. Hold bulk production until I approve that sample.” This gives the production contact a file, a scope and a next step. If the team is ready for bulk production, I name that permission and record any separately approved sample or specification it relies on. I avoid a standalone “approved” next to several attachments. I keep the approval email with the exact files it refers to.

### I record acknowledgment and handle substitutions

I ask the supplier to acknowledge the revision and permitted step. If they intend to use a production export with a different filename, I ask them to identify the source and explain any transformation that affects the approved artwork. I decide whether the export or resulting proof needs another review. This matters most when the supplier has changed a colour separation, shifted a cutting path or prepared several SKUs together. A release record should help the next person identify the file even if the original reviewer is out of the office.

I store the approved PDF, annotated record, resolved corrections and acknowledgment together. When a reorder arrives, I check the job and specification before reusing the approval. A change to printed content, structure or processing can affect what needs checking. I add a new entry and keep the old release for traceability.

## Conclusion

I approve one identified revision at a time. My record connects the correction, evidence, reviewer and next authorised production step.
