How do I place a QR code on a reflective pouch?

By PackHubGlobe Editorial Team · 10 November 2026

I can scan a QR code on a screen and still lose the scan when the printed pouch catches a bright light.

I place the QR code on a stable panel with a plain, opaque background and a clear border. I test it on a filled pouch under the lighting and scanning conditions it will actually face.

I decide what the scan has to do before I choose the spot. A customer opening a web page and a cashier identifying an item may need different checks.

Where should the code sit on the filled pouch?

A panel can look flat in the artwork and curve sharply once the pouch is filled. I choose the position on the real pack.

I place the code away from the gusset, seals, zipper and other areas that bend or wrinkle. I compare candidate positions on samples filled to the intended level.

I check the panel in its selling position

I stand the filled pouch as it will appear on the shelf. I turn it through the angles a customer might use without flattening the film by hand. I look for the part of the panel that changes shape least. I also look for places where a zipper ridge, gusset fold or sealed edge distorts the image. If the front face bends around the product, I check a position farther from that bend and compare the result on the reverse side.

I put a temporary code at each candidate position to compare the geometry. I include the complete code area and its margin in the mockup. I do not use the temporary paper patch to judge how the actual film will reflect light. I check that later with a printed sample. I use the guide to pouch formats to describe the panel and folds when requesting a sample from the converter.

I also consider how the pouch is held. A position close to a grip area may be hidden by a thumb. A code near the tear line can disappear after opening. If the code leads to instructions needed after purchase, I check that it survives opening and remains visible when the contents are partly used.

How do I keep reflective film from interfering with the print?

Dark ink can look legible head on and disappear against glare at another angle. I specify the background as part of the artwork.

I ask for an opaque, uniform background behind the whole QR symbol and its quiet zone. I keep decorative film, spot finishes and other graphics away from that clear area.

I treat the background as a print feature

I ask the converter how the background will be made on the exact film. It may need a white ink layer or a different finish in the code area. I check the coverage of that layer, including the border. A small box of white behind only the dark pattern can leave reflective film where the quiet zone should be. I ask for the code and background on the print proof, with the intended ink and finish identified.

DENSO WAVE's QR guidance specifies a four-module margin around a QR Code.1 I check the actual module size after the designer scales the symbol. I do not measure the margin by the apparent size of the artwork file. I inspect the exported file and make sure neither the background graphics nor a separate label overlaps the required clear area. If a retailer has a specification for the symbol, I review that specification before setting the final dimensions.

Artwork feature What I check on the printed pouch
Dark modules Sharp edges and consistent contrast
Opaque background Uniform coverage across the symbol and its border
Quiet zone The required clear area around the complete pattern
Decorative finish No interference with the code area

I use the packaging print proof guide to keep this check tied to the agreed film and artwork. A proof on plain white paper can show the layout while leaving the reflection question unanswered.

Which scan tests should I run on the printed pouch?

A phone can read a code once under office lighting. I need to see how it behaves in the places the pack will be used.

I scan actual filled pouches at several angles under representative lighting. I check the intended devices and verify that the result leads to the correct item or page.

I compare practical scans with the required verification

I start with a printed sample made with the intended film, white layer and finish. I scan it from the distance and orientation the user is likely to try. I repeat under overhead lighting and near a bright spot that can reflect off the pouch. I note where I have to tilt the pack to get a response. If the pouch has several fill levels, I try both a full pack and one in the condition expected when the code is used.

I record the device, lighting, sample version and outcome. I also open the result and verify the destination. If a customer sees a variant-specific instruction, I check that the printed code links to that variant. If I use the code at retail checkout, I confirm what the retailer's scanning workflow expects. GS1's retail guidance discusses how 2D symbols fit into point-of-sale implementation and addresses packaging effects on scan performance.2

A successful phone scan is useful evidence for customer use. I ask the retailer or verifier which acceptance criteria apply if the symbol needs to pass a formal check. I use the print proof approval checklist for general proof discipline and keep the flexible pouch checks in this article's record. I retain both the practical results and any formal verification report.

How do I prevent a passing design from changing at reorder?

A supplier can keep the same graphic and change the film or finish. I tie approval to the print construction and the actual code.

I record the pouch construction, code artwork, background layer, finish and test sample. I ask for a repeat check when the film, fill, layout or code content changes.

I make the approval easy to reproduce

I keep a copy of the code file and confirm which data or address it encodes. I save the approved artwork revision and the dimensions of the code area. I ask the converter to record the film and the process used to make the opaque background. I also retain a filled sample reference and the conditions used during scanning. If another team reviews the order later, it can see which version was actually checked.

I tell the designer what changes trigger a new proof. Moving the code closer to a seal changes the geometry. Replacing the film or the finish changes the way it reflects light. Changing the encoded content can change the code pattern. I look at the new printed sample and repeat the checks affected by the change. I keep the supplier's production approval separate from any approval for a draft or screen proof.

At receipt, I pick representative samples and compare the code area with the approved version. I check that the destination is still available and that the correct variant carries the correct symbol. If a code fails, I record whether the fault follows one print batch, one orientation or one lighting condition. I use that record to decide whether the converter needs to review placement, print coverage or the underlying code file.

Conclusion

I place the code on a stable, opaque area and approve it only after checking the filled pouch under the conditions where it must scan.
